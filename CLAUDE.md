## 1. What this project is

**PU_PlatePrescorer** — Jan Christopher Spies and Luka Praprotnik Čurič, Glorius group,
Organisch-Chemisches Institut, University of Münster. Target: a full paper in JACS or higher.

**Thesis.** Positive-Unlabeled learning on **real literature reaction data**, combined with a
**virtual (enumerated) unlabeled substrate space**, pre-scores an HTE substrate matrix well enough
to **raise the plate hit rate** — including for reaction classes with **no existing HTE dataset**.

**Relation to prior group work.**
- **PAYN** — *"Positivity is All You Need": Yield Prediction of Organic Reactions in Biased Data
  Sets via Positive-Unlabeled Learning.* J. Am. Chem. Soc. 2026, 148, 15066–15075.
  DOI [10.1021/jacs.6c00127](https://doi.org/10.1021/jacs.6c00127) ·
  code <https://github.com/GloriusGroup/PAYN>
- **TACIT** — feasibility from positive-only data via implicit negatives (under revision).

PAYN used **synthetic** P and U carved from HTE sets. This project uses **real literature
positives** and a **virtual U**, with real, unmodelled reporting bias, and validates
**prospectively** on a wet-lab plate.

**Validation hierarchy:** validation split → held-out public HTE test, touched once
(Chemlex, HiTEA) → **prospective plate: model-picked vs random**, model and scores frozen and
committed before any well is run.

## 3. Rebuild rules

- **Never copy code from `v0-prototype`.** Read it for ideas; anything taken over is rewritten,
  tested and understood.
- **Design before code.** A stage is implemented only after `docs/design/rebuild.md` describes it
  (inputs, outputs, tools, how it is verified) and Jan and Luka agree.
- **Tests first, then code.** Every module in `src/` has tests in `tests/`. Chemistry tests use
  hand-checked examples (the golden set).
- **Nothing merges that its author cannot explain line by line.**
- **Prefer established libraries** (RDKit, rxnutils, chython, RXNMapper) over custom code.
  Test a library on our hard cases before relying on it.
- **Chemistry choices live in versioned config files**, not in code: reaction-class definitions,
  condition families, the definition of a positive.
- **One standardisation for all data.** P, U and TEST pass through the same function; every row
  carries `std_version`.
- **Nothing is dropped silently.** Each stage writes its output table, a short report and the
  rejected rows with a reason.
- **No empty scaffolding.** A folder or file is created when real code needs it. Before creating
  one, say where and why.
- Experiments go in a git-ignored `scratch/` (add it to `.git/info/exclude`). Delete old code;
  never keep `_old` / `_v2` copies or commented-out blocks.

## 4. Working agreement

- **Branch + pull request for every change.** Never commit to `main`. One task per branch;
  PRs of roughly 100–300 lines; reviewed before merge.
- **`LAB_JOURNAL.md` is append-only.** New dated, author-tagged entry at the top; never rewrite
  an old entry. Context → what was done → result → interpretation → next.
- **Decisions** get their own file: `docs/decisions/NNN-title.md`. Accepted decisions are
  superseded, never rewritten.
- **Literature notes:** one file per paper in `docs/literature/notes/`.
- **Negative results are recorded, not discarded.**
- **Never tune on TEST.** Model selection on validation only; test touched once.
- Personal Claude memory is not shared with collaborators — anything a collaborator needs goes
  in this repo.

## 5. Coding standards

- **Package manager: `uv`.** `uv run …`, `uv add …`, `uv sync`. Never bare `pip`.
- **Python 3.13.**
- **Typed and documented:** full annotations, Google-style docstrings, comments for
  non-obvious logic. Functions short (about one screen).
- **Logic in `src/platepu/`; `scripts/` are thin entry points** that parse arguments and call
  `src/`.
- **Quality gates before every commit:**
  `uv run ruff check . && uv run ruff format . && uv run mypy src && uv run pytest`
- **Reproducibility:** raw data immutable; derived data regenerated by scripts with a
  provenance record; fixed seeds; no secrets.
